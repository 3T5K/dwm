# ltcols

A simple framework to allow easy customization of border colors.

Border colors are considered to be attributes of a layout. Each layout function,
i.e. `tile` or `monocle` can be mapped to a paint function in the `ltcols_map`
array. The dispatcher always only uses the first match from this array. If an
elements `arrange` is `NULL`, this is considered to be the floating layout.
Elements whose `paint` is `NULL` are skipped.

```c
static LtColsPair ltcols_map[];
```

A paint function expects a client whose borders might need to be repainted and
an event. As such, its type must be `void(Client *, int)`.
There are four events:

```c
enum {
    LtColsEvLayout,
    LtColsEvManage,
    LtColsEvFocus,
    LtColsEvUnfocus
};
```

The last three events are generated by the dispatcher which hooks the respective
functions. `LtColsEvLayout` should be generated by implementations inside the
arrange function of the layout they're providing colors for.

A client can be considered special in a way that a layout doesn't account for.
For example, a scratchpad. Paint functions for such clients can be provided in
the `ltcols_overrides` array. The dispatcher will use `ltcols_override` on a
client and will not invoke the layouts paint function if it returns `1`.

```c
static LtColsOverride ltcols_overrides[];
```

Implementations should either implement colors for a layout or for some kind of
a special client. In the latter case, a predicate which identifies the special
clients and a paint function that considers all events must be provided.

In the former case, the arrange function of the layout must be adapted to update
the borders and the respective paint function should handle at least the last
three events. `LtColsEvLayout` can technically be handled directly within the
arrange function. Depending on complexity, that might be desirable.

Arrange functions normally only handle tiled clients. Implementations must
consider all visible clients. Clients can have their border color overriden by a
different paint function. Therefore, arrange functions must invoke
`ltcols_override` with the `LtColsEvLayout` event on every visible client and
skip it if `ltcols_override` returns a non-zero value.

Border color changes should be applied with `ltcols_try_paint`.

## functions

### ltcols_override

```c
static int ltcols_override(Client *c, int ev);
```

Attempts to find an element of `ltcols_overrides` whose `match` function
produces a non-zero value when called with `c`. If such an element is found, its
`paint` function is invoked with `c` and `ev`, and `1` is returned. The search
is done linearly and only the first match is used. Elements whose `paint` or
`match` is `NULL` are skipped. Returns `0` if no viable element is found.

### ltcols_map_paint

```c
static void ltcols_map_paint(void (*paint)(Client *, int), Monitor *m, int ev);
```

Maps `paint` over all clients of `m` that are visible and have no overrides.
A client `c` is visible if `ISVISIBLE(c) != 0` and has no overrides if
`ltcols_override(c, ev) != 0`. If `m` is `NULL`, nothing happens. If `paint` is
`NULL`, `ltcols_paint_default` is mapped.

### ltcols_nextvis

```c
static Client *ltcols_nextvis(Client *c);
```

Finds the next visible client if `c` is not. If no such clients exist, or `c` is
`NULL`, `NULL` is returned.

### ltcols_paint_default

```c
static void ltcols_paint_default(Client *c, int ev);
```

Invokes `ltcols_paint_template` with the active color being
`{SchemeSel, ColBorder}` and the inactive being `{SchemeNorm, ColBorder}`.

### ltcols_paint_template

```c
static void ltcols_paint_template(Client *c, int ev, LtColsIdx ac, LtColsIdx in);
```

A basic event handler. Usually enough for simple layouts. If `c` is deemed
active, its border becomes `scheme[ac.row][ac.col]`. Otherwise, it becomes
`scheme[in.row][in.col]`. If `c` is `NULL` or `ev` is invalid, nothing happens.

### ltcols_try_paint

```c
static void ltcols_try_paint(Client *c, unsigned long col);
```

A function that paints the border if `col` is different from the current border
color of `c`. The current border color is considered to be `c->ltcols_color`. If
the border is repainted, this field is updated. Does nothing if `c` is `NULL` or
`col` is `LTCOLS_NOCOL`.

## structs

```c
typedef struct {
    void (*arrange)(Monitor *);
    void (*paint)(Client *, int);
} LtColsPair;

typedef struct {
    int (*match)(Client *);
    void (*paint)(Client *, int);
} LtColsOverride;

typedef struct {
    size_t row, col;
} LtColsIdx;
```
